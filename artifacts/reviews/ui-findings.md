2. severity: high | screenshot/page: `timeline.png` | issue: Loop selector text (`1 2 3 4 5 6 +2 .`) appears clipped/ambiguous at the end of strips, suggesting overflow or truncated token rendering. | brief suggested fix: Enforce fixed token width with overflow handling (ellipsis or wrap) and remove ambiguous trailing glyphs.
3. severity: medium | screenshot/page: `timeline.png` | issue: Top control clusters (transport/mode/quantization/etc.) have weak hierarchy; active states are hard to distinguish from static labels at a glance. | brief suggested fix: Increase state contrast and group controls with clearer section titles or spacing blocks.
4. severity: medium | screenshot/page: `mappings.png` | issue: The table is very dense; row actions/states (`SCOPE`, `ON`) read like plain text and don’t clearly communicate interactivity. | brief suggested fix: Add clearer affordances (button styling, toggles, active row emphasis) and slightly increase row height/column separation.
5. severity: medium | screenshot/page: `mappings.png` | issue: Shortcut strings are inconsistent/unclear (`SHIFT+? .`, `Z X D F` style entries), which slows scanning and increases misread risk. | brief suggested fix: Normalize shortcut formatting (single canonical notation and consistent separators).
6. severity: low | screenshot/page: `mappings-overlay.png` | issue: Overlay shows `ROWS 1-19 / 30` but there is no obvious scroll affordance, and the large empty lower area looks unfinished. | brief suggested fix: Add visible scrollbar/page controls and use empty space for help text or compact the modal height.
7. severity: medium | screenshot/page: `midi-io.png` | issue: Device cards are mostly empty gray blocks with minimal metadata, so selected/default state is not immediately obvious beyond tiny corner tags (`DEF`, `SEL`). | brief suggested fix: Promote state badges with stronger contrast/size and add key metadata (channel/activity) to each card.
8. severity: medium | screenshot/page: `routing.png` | issue: Right-side action labels vary by row (`TAP +/-`, `SELECT`, `TOGGLE`) without a consistent interaction model, which is misleading. | brief suggested fix: Standardize control patterns (same control type for same operation class) and show contextual hints only on focus.
9. severity: low | screenshot/page: `routing.png` | issue: `ACTIVE T1`/`THRU OFF`/`TRACK 1` region mixes status and navigation without clear grouping. | brief suggested fix: Split into distinct “track selection” and “routing status” groups with explicit labels.
10. severity: low | screenshot/page: `timeline-focused.png` | issue: Focused mode improves readability, but `SONG/DUAL` and similar mode chips still look like static text and can be mistaken for labels instead of controls. | brief suggested fix: Differentiate control chips from labels via stronger button styling and consistent active/inactive states.
